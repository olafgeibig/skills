# Adopt a Flat Project

Use when an existing `flat` project in `projects/<x>/` should become a `dossier-project`. Adoption is an approved change to both the manual and the notes, not a side effect of project setup.

1. **Inventory without writing.** Read the project and vault manuals, inventory source notes and open task IDs, and capture a rollback baseline. Collect all pages of TurboVault `graph_report(kind="broken_links")` and record the concrete `(source_file, target)` pairs, including those outside the project. Counts alone miss a new break that replaces an old one.
2. **Propose the cut.** Name each dossier and each case with its closing condition. Map every source note to a target path, class and parent or a deliberate keep/merge/retire decision; map each open task ID to exactly one case. Assign old history to existing evidence, a substantive event, a curated milestone or a deliberate omission. Do not invent missing provenance. Check vault-wide basename collisions before proposing moves.
3. **Wait for approval before any write**, including changing the manual, creating notes or moving tasks. After approval, declare the new type per `hermes-projects` and apply the approved mapping through TurboVault. Keep the router dossier-focused. Repair inbound links from inside **and outside** the project, and sweep raw text for old basenames and paths; unresolved links may not appear in the indexed link table.
4. **Preview and approve generated changes separately.** Run `check.py --rebuild <project>` and apply only the approved diff through TurboVault. Re-run it for idempotence; run `--report` and review `--audit`. Compare open task IDs and the full broken-link pair sets against baseline. Resolve every newly introduced pair, including those with external sources or targets; report unrelated concurrent changes separately. Report what moved, what was retained or retired, and what remains open.
